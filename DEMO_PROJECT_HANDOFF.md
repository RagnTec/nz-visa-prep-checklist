# Demo Project Handoff Contract

Operational handoff contract generated by the canonical development repository for consumption by the Demo repository (`nz-visa-prep-checklist`).

## 1. Source Provenance
- **Source Repository**: `nz-student-visa-checklist`

- **Package Version**: `0.1.0`
- **Export Schema Version**: `1.0.0`

## 2. Runtime Compatibility & Architecture
- **Application Hub & Continuity**: The application includes multi-applicant workspace management and application continuity. Users can navigate between Hub and Application views.
- **Survey Resume Continuity**: Survey page progression is persisted per application. Returning to an incomplete application restores the last active survey page.
- **SurveyJS Dynamic Import Boundary**: SurveyJS (`survey-core`, `survey-react-ui`) and Survey CSS are strictly lazy-loaded via the Survey workflow boundary (`SurveyWorkflowView`). The initial application shell bundle does not load SurveyJS.

## 3. Deployment & Build Requirements
- **Complete Source Snapshot**: The Demo repository is an independent source repository that builds its own production assets via `npm run build`.
- **Complete Dist Upload**: Deployment to GitHub Pages must deploy the entire generated `dist/` directory to ensure all asynchronous split chunks (e.g., `SurveyWorkflowView-*.js`, `SurveyWorkflowView-*.css`) are served.
- **Dynamic Chunks & No Fixed Asset Names**: Asset filenames are dynamically generated by Vite with content hashes. The deployment pipeline must not assume fixed chunk filenames.
- **Base Path**: The Demo workflow sets `VITE_BASE_PATH: /nz-visa-prep-checklist/` in `.github/workflows/deploy-pages.yml`. Vite's `base` configuration resolves this dynamically.

## 4. Public Boundary Guarantees
- **Internal Development Excluded**: Development fixture loaders (`src/dev/`), internal documentation, agent instructions, and export tooling are excluded from this snapshot.
- **Local-First Privacy**: All state is stored in browser-local IndexedDB and localStorage using the public `nzVisaPrepChecklist` namespace. No telemetry or cloud analytics are included.

## 5. Recommended Demo Compatibility Verification
When validating the deployed Demo:
1. Verify shell, Home, and Application Hub load cleanly without errors.
2. Verify creating/selecting an application enters Survey and loads the dynamic Survey chunk.
3. Verify refreshing an incomplete survey restores the saved page location.
4. Verify completing survey questions navigates to Checklist.
5. Verify network requests for async chunks do not return 404.
